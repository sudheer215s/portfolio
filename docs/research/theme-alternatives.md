# Theme alternatives for Sudheer Singh — 2026 engineering portfolio

**Researcher role:** design research only. No code. No repo edits.  
**Subject:** Sudheer Singh — AI Systems Builder; Scientist-B / backend at C-DOT (India’s telecom R&D lab); flagship personal project ClauseNotebook (citation-grounded 3GPP copilot).  
**Charge:** five unique, non-generic visual themes that are *not* Nothing and *not* JDoodle; pick a primary and a runner-up. Unique ≠ unserious.

**Verdict up front.** Primary: **TS 00.001 — Standards Document as Product.** Runner-up: **Field Instrument — C-DOT Bench.** Do not mash them. Build one language.

## 2. What “unique” means here (and clichés to ban)

Unique, for this site, is not “never seen on Awwwards.” Unique is: **a hiring manager at an applied-AI / infra / developer-tools company can identify this tab in 400ms, and still extract proof in 29 seconds.**

Sudheer is not a creative technologist. He is a production backend engineer who happens to be building a standards copilot, with national-scale IMS/ENUM numbers behind him. The visual language should feel like a **designed product or editorial object** whose content is the product: clauses, provenance, uptime, citations. Not a costume.

### Banned (2026 junior-portfolio default)
- Dark glassmorphism; purple/blue/indigo gradients; mesh gradients; “aurora” blobs.
- Three equal project cards in a row; bento grids; Aceternity/Magic UI kits.
- Inter, Roboto, Space Grotesk, Geist-as-identity, SF Pro as the whole voice.
- Gradient text; “Hi, I’m a passionate developer”; “I love to code.”
- Particle.js; Three.js / R3F hero that hides content; scroll-jacked camera splines.
- Green-on-black CRT terminal; ASCII boot sequence; fake `root@sudheer:~$`.
- Linear clone: `#08090a` + `#5e6ad2` + Inter 510 + negative tracking 80px H1.
- Nothing clone: NType, glyph dots, transparent-phone photography, signal crimson `#ff0033` as the brand.
- JDoodle clone: orange playground IDE skin as the entire identity.
- IBM Blue `#0f62fe` + Plex + 0-radius buttons = Carbon cosplay.
- Saffron/tricolour “Indian tech” kitsch. C-DOT is a lab, not a tourism board.
- Fake live NOC maps, pulsing 5G towers, WebGL globes labelled “telecom.”
- Invented metrics, fake repo links, overclaimed AI depth (already in the subject brief).

### What unique is allowed to be
- **Object-like:** the site has a format (a spec, a bench plate, a poster, a ledger), not a “layout.”
- **Typed, not illustrated:** hierarchy from type + grid + one accent, not from illustration packs.
- **Dense where density is honest:** numbers, clause IDs, hashes, versions. Sparse where sales sites are sparse.
- **Static-first:** CSS, maybe 20 lines of JS for TOC/search. No WebGL required.
- **Serious:** a staff engineer would not be embarrassed to paste this in a hiring channel.

Awwwards in 2025–26 is a trap. The annual prize is a rendering contest. Pangram Pangram remains the useful exception: type as the object. Stripe Press is the useful editorial exception: the artifact *is* the page. Teenage Engineering is the useful industrial exception: chrome disappears so the engineered object can speak. IBM Carbon is the useful *discipline* exception, not the look. Bloomberg is the useful *density ethics* exception, not the amber-on-black skin.

## 3. Five candidate themes

### Candidate A — TS 00.001: Standards Document as Product

**One-line:** The portfolio is a designed 3GPP-style technical specification you can actually read.

Not a PDF screenshot. A *productized* spec viewer: running identity, clause tree, modal verbs, annexes, change history, conformance results. The joke, if there is one, is so dry it reads as competence.

#### Visual / interaction principles (10)
1. **Type:** IBM Plex Serif for running text (spec body without Times); IBM Plex Sans for UI chrome and H1; IBM Plex Mono for clause numbers, hashes, versions, code, SHALL. Optical sizes: serif ~18–20px body / 1.55–1.7 line-height; mono 12–13px tabular.
2. **Color:** Paper canvas `#F3EFE4` or `#EDE6D6` (aged spec stock, not hipster beige). Ink `#1A1916`. Hairline `#C4BBA8`. **One** signal: a restrained stamp red `#B42318` used only for the document class banner (“TECHNICAL SPECIFICATION”), the live availability chip, and focus rings. No IBM Blue. No phosphor green.
3. **Grid:** Document grid, not marketing 12-col. Left rail 4.5–5.5rem for clause IDs (`4.2.1`); measure ~66–72ch for prose; right margin for “see also” / GitHub / live. Mobile: clause ID becomes a kicker above the heading, not a squeezed sidebar.
4. **Chrome:** Persistent running header: `SUDHEER TS 00.001` · `V1.0.0 (2026-09)` · `page n`. Footer: `© Sudheer Singh` · SHA-256 of the page or git short hash · `Status: Released`. This is the brand, not a logo mark.
5. **Structure as IA:** Clause 1 Scope (positioning). Clause 2 References (links, not a blogroll). Clause 3 Definitions (stack, terms: RAG, evals, tracing — defined, not buzzed). Clause 4 Architecture of experience (C-DOT). Clause 5 Work items (projects, each a numbered subclause). Clause 6 Conformance (the proof numbers). Annex A Contact. Annex B Change history.
6. **Modal voice:** Body copy may use *shall / should / may* only where it is true (“ClauseNotebook shall not emit an uncited claim”). Everywhere else, plain engineering English. Do not write the whole site in RFC-speak; that becomes costume.
7. **Motion:** Almost none. Instant clause jump from TOC. `:target` highlight. No parallax. Sticky TOC on desktop; a compact “clause map” drawer on mobile. Optional: in-page search that filters headings (CSS + tiny JS).
8. **Figures:** Projects are not cards. Each is a **clause with a conformance table**: problem, constraint, stack, proof metric, repo, status (`registered | converted | released` borrowed from ClauseNotebook’s state machine). One diagram max per project, drawn as a spec figure (numbered, captioned, hairline, no isometric 3D).
9. **Citation chrome:** Inline citations `[TS 23.501]` `[repo]` `[metric]` as superscript or bracket tokens. Hover/focus reveals the source. Uncited superlatives are banned by the design system itself.
10. **Print and a11y:** `@media print` should produce a readable spec. Contrast ≥ 4.5:1. Skip links. Heading outline *is* the clause tree. Reduced-motion: no animation at all.

#### Why it fits Sudheer specifically
He already lives in this format. NSSAAF work cites 3GPP TS 23.501 / stage-3 docs. ClauseNotebook *is* a clause-aware, provenance-first reader. C-DOT is a 3GPP-adjacent national lab (TSDSI member). The proof numbers (99.99% uptime, 40% faster queries, 70% less manual deploy, first-submission zero non-conformances) look native in a conformance table and fake in a “What I Do” bento. Hiring managers for “applied AI over technical corpora” get the thesis in one glance: this person treats documents as systems.

#### Why it would look unique in 2026
Nobody in the Brittany Chiang / Aceternity / Linear-clone cohort will ship a spec. Awwwards is a 3D arms race; this is the opposite object. IETF is *just now* (2026) rebuilding rfc-editor.org around reading. A personal site that is a designed spec viewer is timely without being trendy. It is also un-forkable: the content *is* the chrome.

#### Risk of looking like a gimmick
**Medium, controllable.** Risks: (a) unreadable pastiche of a scanned ETSI PDF; (b) too many *shall*s; (c) looking like a government intranet; (d) clause numbers as decoration with marketing copy underneath. Mitigation: real hierarchy, real citations, paper not #FFFFE0, Plex not Times New Roman, one red stamp not a coat of arms, and a hero that still states the job he wants in a sentence a recruiter can paste.

#### Feasibility (static / cheap)
**Highest of the five.** HTML + CSS. Optional: heading-id TOC, client-side filter, copy-hash button. Host on GitHub Pages / Cloudflare Pages. No WebGL. Fast LCP if fonts are subset and self-hosted. Mobile is a linear spec, which is a solved problem (see RFC HTML).

#### Legal notes (fonts)
- **Use:** IBM Plex Serif, Sans, Mono — SIL OFL 1.1. Self-host WOFF2. Keep Reserved Font Names; do not rename a derivative “IBM Plex.” Include `OFL.txt` in the repo.
- **Do not use:** Times, Liberation Serif as the *voice* (looks like a raw ETSI PDF). IBM Blue. Carbon components (Apache-2 code is fine legally, wrong culturally). Any 3GPP / ETSI logo. Do not reproduce ETSI cover layouts so closely that it implies official publication.

### Candidate B — Field Instrument: C-DOT Bench

**One-line:** The site is a piece of lab equipment: a field recorder for production systems.

Teenage Engineering’s *object* language (not their fonts, not their orange) crossed with a government R&D bench: serial plates, calibrated readings, aluminum and paper, one physical accent from the hardware — never from a SaaS palette.

#### Visual / interaction principles (10)
1. **Type:** Fragment Mono (OFL) for labels, serials, nav, metrics — industrial Helvetica-mono, not “coder mono.” IBM Plex Sans Light/Regular for body. Optional Newsreader at display size for the one human sentence on the plate. No Univers TE, no NType.
2. **Color:** Warm off-white `#F6F3EC` and true black `#0B0B0B` as dual modes (bench / night watch). Aluminum `#C8C4BC`. One accent from *instrument*, not brand decks: a tungsten amber `#D97706` *or* a deep instrument teal `#0F5C66` — pick one, never both. Products/photos may carry local color; chrome stays grey.
3. **Radius:** 0px on plates, 2px max on inner controls. No squircles, no 16px cards.
4. **Grid:** Catalog + plate. Homepage is a **faceplate**: name, role, one sentence, three calibrated readouts (uptime, query improvement, deploy-time cut) as engraved metrics with units. Below: a product row of *work items* as photographed objects (diagrams, CLI output, architecture as line art), not cards with gradient thumbs.
5. **Chrome:** Screw-like registration marks, hairline ticks, a serial `CDOT-BE-2024` / `CLNB-0.x` as wayfinding — used sparingly. A physical “spec sheet” fold under each project (weight, stack, constraint, result).
6. **Photography / figures:** High-key product shots of *documents and terminals as objects* (a printed TS, a Grafana panel, a CLI). No 3D phone. No fake lab glassware. Line diagrams in 1px stroke.
7. **Motion:** Mechanical, not cinematic. Faceplate metrics count up once on first view (respect `prefers-reduced-motion`). Hover = a plate sliding to reveal the spec sheet, 180–220ms ease-out, no bounce. No scroll jacking.
8. **Density:** Labels at 10–11px uppercase, +0.08–0.12em tracking. Body 16–18px. Metrics in Fragment Mono tabular lining nums. Whitespace is *bevel*, not luxury margin.
9. **Interaction model:** Like TE’s store: the object is clickable; the page is not a story. Deep pages are spec sheets. Contact is a stamped `mailto` on the plate, not a form with floating labels.
10. **Mobile:** Faceplate stacks; metrics become a 2×2 engraved grid; spec sheets are accordions. Touch targets 44px even if labels are small (hit area ≠ type size).

#### Why it fits Sudheer specifically
C-DOT is a lab. He rebuilt a PostgreSQL cluster, SS7/SIGTRAN number portability, 5G-core interfaces. That work is *instrumented*. The 99.99% / sub-30s recovery / millions of lookups/day numbers want to be **readouts**, not testimonials. ClauseNotebook as a field instrument for 3GPP (a handheld spec tool) is a better metaphor than “AI startup landing.” Product-company hiring managers already admire TE, Teenage-adjacent hardware, and Linear’s restraint; this is that seriousness without Linear’s look.

#### Why it would look unique in 2026
TE’s language is famous in industrial design and almost unused in engineer portfolios (which went terminal-green or glass). Nothing made *transparent consumer electronics* the cliché; this is *opaque lab object*. Warm paper + mono labels + zero radius is rare next to dark SaaS. It photographs well in a hiring Slack screenshot.

#### Risk of looking like a gimmick
**Medium.** Risks: synth-brand fan site; steampunk screws; dashboard-cosplay; copying Nothing’s glyph dots “because hardware.” Mitigation: no cartoon screws, no LED matrices, no orange `#ff6600` (TE’s), no crimson `#ff0033` (Nothing’s). If a decoration does not label a real quantity, delete it.

#### Feasibility
**High.** CSS grid, hairlines, one optional count-up. Images must be designed (SVG spec sheets, not Unsplash labs). No WebGL. The hard part is art direction of the plates, not engineering.

#### Legal notes
- Fragment Mono, IBM Plex Sans, Newsreader: SIL OFL 1.1. Self-host. Respect Reserved Font Names.
- Do **not** use Teenage Engineering wordmark, OP-1 imagery, TE-20/TE-40.
- Do **not** use Nothing NType/NDOT or Glyph-like LED grids.
- C-DOT wordmark: only if usage policy allows; safer to say “Centre for Development of Telematics” in text.

### Candidate C — Swiss Grid Poster (International Typographic)

**One-line:** Each section is a Müller-Brockmann concert poster: modular grid, one grotesque, one red, type as the image.

#### Visual / interaction principles (9)
1. **Type:** IBM Plex Sans Condensed or Uncut-adjacent **Archivo** (OFL) in 3–4 weights. One family. Display at 72–120px, flush-left, tight leading 0.9–1.0. Body 16–18px, ragged right. No serif required; if used, Source Serif 4 for pull quotes only.
2. **Color:** White `#FAFAFA` or cold grey `#E8E8E8` canvas. Black `#111`. One poster red `#E30613` (or a colder `#C8102E`) for rules, the availability verb, and one word in the H1. Photography stays greyscale.
3. **Grid:** Explicit modular grid (e.g. 8 columns × baseline 8px) *shown* as hairlines in the header or on hover of a “grid” toggle — then hidden for reading. Every edge snaps. Asymmetry: H1 occupies columns 1–6, meta 7–8.
4. **Hero:** Not a greeting. A poster: `SINGH` oversized; `AI SYSTEMS / BACKEND / 3GPP` as a stacked kicker; one red rule; the short phrase from the brief as the only sentence.
5. **Projects:** Each project is a **poster spread**, not a card: huge title, one metric as a figure, a short abstract, a red index number (`01 / 03`). Horizontal rules, not shadows.
6. **Motion:** Type only. Words can reflow or a red rule can grow 200ms. No images sliding. No Lenis unless it does not steal wheel events from readers.
7. **Chrome:** Bare. Nav is a column of verbs. Footer is a colophon (typefaces, git hash, last spec release).
8. **Photography:** Infrastructure, not headshots-with-bokeh. If no real photos exist, use diagrams and type — do not fake a photo essay.
9. **Mobile:** Posters become a single column with the same type scale stepped down; do not keep 120px type on a phone.

#### Why it fits Sudheer
Swiss style is the graphic language of *standards and wayfinding*. It is how serious labs and transport systems already speak. It makes MANIT → C-DOT → product-company read as a clean trajectory, not a storytime. Hiring managers can screenshot one poster-section and the metric is still legible.

#### Why unique in 2026
Swiss-on-the-web is usually Inter + lots of white space + a circle avatar (i.e. not Swiss). Real poster scale + condensed grotesque + visible grid + one red is rare in engineer sites. Awwwards ignores this because it will not win SOTY. That is the point.

#### Gimmick risk
**Medium-high if lazy.** “Swiss” is how agencies describe any black/white site. Risk of looking like a template called “Helvetica Portfolio.” Mitigation: condensed type, poster-scale type, shown grid, no Inter, no circles, no 1:1 avatars in the hero.

#### Feasibility
**Highest-equal with A.** Pure CSS. The skill is typesetting, not libraries.

#### Legal notes
- Archivo, IBM Plex Sans Condensed: OFL. Helvetica / Neue Haas Grotesk are **not** free; do not pirate them. Akzidenz-Grotesk is not free. Fragment Mono can pair as the “mono Akzidenz.”
- Do not reproduce Müller-Brockmann posters or Zürich concert IP.

### Candidate D — Citation Ledger: Provenance Editorial

**One-line:** A Stripe Press issue about one engineer, where every claim has a hash and a source.

Magazine object + cryptographic receipt. Built for the ClauseNotebook thesis and for AI-hiring skepticism (un-cited portfolios are now a smell).

#### Visual / interaction principles (9)
1. **Type:** Newsreader (opsz) for display and body; IBM Plex Sans for UI; IBM Plex Mono for hashes, SHAs, clause IDs. Enable `opsz` so 48px display and 18px body are different cuts.
2. **Color:** Book cloth / cream `#F7F1E8`, navy ink `#0D1B2A` (Stripe-like navy, not black), one ink-red for citations. No purple CTAs. No Söhne, no `#533afd`.
3. **Layout:** Issue architecture. Masthead `SINGH / VOL. 01 / 2026`. Table of contents. Long opening essay (the positioning paragraph, not a bio). Then reported pieces: C-DOT, ClauseNotebook, TranslateLive, the NestJS backend. Colophon.
4. **Provenance rail:** Every numeric claim has a footnote leading to a **ledger row**: claim, source (repo path, internal system — if internal, say so), date, optional SHA. This is the design, not a tooltip gimmick.
5. **Figures:** Pull quotes of *metrics*, not of “passion.” Full-bleed only for one diagram per piece.
6. **Motion:** Page-turn none. Image fade ≤150ms. Footnote jump with `:target`.
7. **Writing:** Editorial, short paragraphs, no “we” corporate. Sudheer in third or first consistently. Hiring CTA is a masthead line: `Open to AI / LLM engineering roles — production reliability.`
8. **Interaction:** Click a citation, the ledger highlights. Optional: copy a citation in academic form. This is the JDoodle “tool” idea in editorial clothing.
9. **Mobile:** Masthead compresses; ledger becomes stacked definition lists.

#### Why it fits Sudheer
ClauseNotebook’s whole point is provenance (versioned JSON, SHA-256, idempotent CLI, abstention). TranslateLive and the social backend are ship stories that want reporting, not icons. Product-company readers (the Stripe Press audience is literally founders and infra people) already trust this object.

#### Why unique in 2026
Most “editorial portfolios” are a serif H1 on a blog. A **ledger of claims** is not a blog. AI-hiring in 2026 is drowning in generated case studies; a site that refuses uncited sentences is a position.

#### Gimmick risk
**Medium.** Risks: looking like Substack; looking like a student journal; SHA-256 theatre on claims that are just “I used FastAPI.” Mitigation: only hash or footnote what is real; keep the masthead short; do not decorate with fake wax seals or blockchain gradients.

#### Feasibility
**High**, with a writing cost. Design is CSS. The work is editing. Static MD/HTML is enough; do not build a CMS.

#### Legal notes
- Newsreader, IBM Plex, Source Serif 4 (alt): OFL.
- Do not use Söhne, GT Sectra, Lyon (paid). Do not clone Stripe Press 3D book covers (WebGL, and brand-adjacent).

### Candidate E — Amber Wire: Professional density (not a CRT)

**One-line:** Bloomberg’s density ethics applied to one engineer’s systems: scannable, amber-punctuated, no terminal costume.

#### Visual / interaction principles (9)
1. **Type:** IBM Plex Sans for UI at 14–16px as the workhorse (Bloomberg’s 14px lesson: do not spend the viewport on a 96px hello). Plex Mono 12–13px tabular for metrics. One display line only, 32–40px.
2. **Color:** Deep navy-black `#0A0E1A` *or* inverted paper with amber ink — pick one canvas. Signature amber `#E39B2A` for live/positive state and the availability pip. Up/down semantics only if you have time-series you will maintain (you do not; so do not fake a ticker). Muted labels `#8B90A0`.
3. **Radius:** 0–2px. Hairlines, not shadows.
4. **Layout:** Multi-pane on desktop: identity + intent | experience table | project stack. Looks like a tool a staff engineer leaves open. Not a four-widget Grafana parody.
5. **Tables > cards:** Experience is a table: org, role, window, proof. Projects are rows that expand. Stack is a tagless list with versions where honest.
6. **Motion:** 50–80ms flash on focus is enough. No blinking cursors. No scanlines. No boot sequence.
7. **Hero:** A status line: `AVAILABLE | AI systems / production reliability | New Delhi`. Then the short phrase. Then the three proof numbers in a row of cells.
8. **Mobile:** Panes stack in a designed order: status, phrase, numbers, projects. Tables become definition lists, not sideways-scroll horror.
9. **Honesty rule:** If a number is not live, do not put a green dot next to it. `as of 2026-07` is more professional than a pulse animation.

#### Why it fits Sudheer
He already thinks in SLOs, failover, detection time, query plans. A hiring manager from infra / observability / AI platform will feel at home. The 99.99% and sub-30s recovery belong in cells.

#### Why unique in 2026
“Terminal portfolio” is a *template category* in 2026 (Seera DevTerminal, etc.). Amber-navy professional density without ASCII art is not that category. Bloomberg’s web is white + 14px; combining *that* restraint with *one* amber pip is enough.

#### Gimmick risk
**Highest of the five.** Very easy to become: hacker movie, Matrix, fake NOC, “cyber” grid, 5G globe. Also easy to become unreadable (11px grey on black). If this ships with scanlines, reject the build.

#### Feasibility
**High** for static tables. Temptation to add fake websockets will wreck it. Ban live data unless it is real.

#### Legal notes
- IBM Plex OFL. JetBrains Mono OFL if needed.
- Do not copy Bloomberg’s yellow keyboard, BLOOMBERG wordmark, or terminal screenshots.
- Amber/black is a *language*, not a trademark, but do not use their proprietary type.
